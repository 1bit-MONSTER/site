# What ships in v2026.43

The release candidate for `v2026.43` is built from the pins below and is waiting on the owner's
tag. This page is the data that goes with it: what changed since 18 October, measured on a Ryzen AI
Max+ 395 (Strix Halo), with the standard each number was taken under. Everything measured after the
23 October 01:38 rebuild is **90 W cap, PCM pad (23 Oct)**; *lemonade bench standard* means Lemonade's
own CI benchmark (reload before every run), *ours* means our sampler standard.

| component | pin |
|---|---|
| llama.cpp (HRX) | `851fa6c8d8f2` |
| hrx-system | `82804197bcbe` |
| Lemonade | `27abcc24da99` |
| our HIP kernels for HRX | `abaa6bc484d5` |
| the sealed NPU kernel sets | `17ed5be7a28a` |

The full pin list, the artifacts and every check are in
[docs/releases.md](../docs/releases.md#v202643-candidate-23-oct).

## The week's speed, on HRX

| change | measured |
|---|---|
| verify step for 2–8 tokens, K-quant | Qwen3.8-27B with MTP, code / prose / short chat: 25.9 / 20.5 / 21.9 → **36.0 / 26.8 / 29.9 tok/s**; the step itself 121 ms → 88 ms |
| decode attention for gated head-256 layers, split-K | Qwen3.5-4B at 32K context **23.7 → 47.1 tok/s**; Qwen3.8-27B **7.5 → 11.0 tok/s** |
| expert formats for Qwen3.8-Flash-Next | **5.1 → 26 tok/s**, 50 with MTP |
| prompt flash attention with causal block skipping | Qwen3-4B, 4,096-token prompt **+45 %** |
| prefill tiles with raster groups | Qwen3.8-27B prefill **+1.6 … 2.5 %** |
| a second warm-up request at load | Qwen3.8-27B short chat time-to-first-token **2.64 → 0.80 s** |
| batched expert decode on our kernels | see the table below |

Decode without MTP is unchanged (about 12 tok/s on the 27B): this week moved the speculative path
and prefill, not plain decode.

## Eight concurrent chats

Aggregate throughput, median of three runs, `-c 8192` per slot, 256-token chats, **ours standard,
90 W cap, PCM pad (23 Oct)**:

| model | N=1 | N=8 | scaling |
|---|---|---|---|
| Qwen3.8-27B (MTP on) | 24.3 | **50.7 tok/s** | 2.08x |
| Qwen3-Coder-30B-A3B | 84.2 | **138.1 tok/s** | 1.64x |
| Qwen3.5-4B | 57.3 | **194.3 tok/s** | 3.39x |

Honest comparison: Lemonade's Vulkan build reaches 201.8 on Qwen3.5-4B and 245.7 on Coder-30B at
N=8 in the same run. The 4B is level; the MoE batching gap is the next speed row, and it is a
batching problem (per-request decode at N=8 is 19.9 tok/s against Vulkan's 31.9), not a correctness
one.

## Correctness

- **Strict placement is the default**: a graph with a single node off the GPU refuses to load, and
  the hardware gate fails the same condition. The census closes **43 of 43** configurations with 0
  nodes off HRX and one graph split ([docs/hw-gate.md](../docs/hw-gate.md)).
- **#315 is resolved.** The CWSR-on soak passed 37 arms over 9 h 03 min with 0 faults.
- **The ZAYA1-8B NaN report is closed**: 120 fresh loads across two pins, 0 NaN aborts, with the
  guard that refuses to sample NaN logits still in place.
- The gate now covers q8_0 KV caches (K and V, and K alone), a mixed-type flash-attention case, an
  MoE model, an IQ-quant model and a second long-prompt needle.

## The NPU

The packages carry **only the sealed NPU kernel sets** — a plaintext artifact fails the packaging
check and the launcher refuses an unsealed one. The gate's NPU phase measures **90.33 tok/s** on the
0.6B model, and the 1bit OS image proves the NPU and the `amd_pmf` sensors from the booted image
([docs/npu.md](../docs/npu.md)).

## Lemonade and 1bit OS

Lemonade now takes **one hop** to the engine: for a GGUF it starts the engine's own `llama-server`,
with the engine's warm-up requests sent first. The catalog carries **22 HRX entries, each proven on
the box** (strict placement, one request in role, `lemonade bench ... chat-short`: 43.4 tok/s on
Qwen3-8B to 330.7 tok/s on Qwen3-0.6B) and 3 NPU entries.

The 1bit OS image carries the new Lemonade and the sealed NPU sets, loads the USB4 v2 / Thunderbolt
stack, and its unified kernel image is signed with the machine's enrolled MOK, so a stick boots with
Secure Boot on.

## What is in the candidate, and what is not

In: `lemonade-onebit-v2026.43-linux-x86_64.tar.zst`, `1bit-os-v2026.43.img.zst` + `.efi`, the binary
drop, `changes.json` and `SHA256SUMS`. Not in: the OS install step (on a branch), and Windows — the
engine ships inside Lemonade, which has its own Windows build.

How to run it, and what every flag does: [docs/serve.md](../docs/serve.md). What the gate checks
before a merge: [docs/hw-gate.md](../docs/hw-gate.md).
