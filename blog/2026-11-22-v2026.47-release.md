# v2026.47: one binary for local LLMs on Strix Halo, GPU and NPU

v2026.47 is the first stable release of the 1bit engine: one binary that serves local LLMs on the
AMD Ryzen AI MAX+ 395 (Strix Halo), on its Radeon 8060S GPU through AMD's HRX runtime and on its
XDNA 2 NPU through our own NPU engine, inside AMD's Lemonade Server. You boot it from a USB stick,
and the machine serves models behind an OpenAI-compatible API. This post covers what ships, what
changed since the first release candidate, what we measured, how to get it, and what comes next.

## What ships in v2026.47: one binary for the GPU and the NPU

Every model is served through `1bit serve`, one binary. On the GPU it runs on HRX using AMD's Loom
kernels in ggml-hrx, with our own kernels for the ops Loom does not cover; on the NPU it runs on our
NPU engine. One binary to rule them all. The 1bit engine is model agnostic: any Hugging Face architecture the
registry maps, any GGUF quantization, Ryzen AI NPU packs and ONNX graphs, served by one Lemonade
backend, the `onebit` recipe ([Meet the engine](overview.html), [Lemonade](../docs/lemonade.md)).

- **The GPU route: HRX with Loom kernels.** HRX is AMD's HIP Runtime Extended. The llama.cpp build
  with AMD's ggml-hrx backend dispatches Loom kernels, compiled by HRX's Loom compiler, and our own
  kernels fill the ops Loom does not cover. Every ggml weight type runs there, including NVFP4, MXFP4
  and the ternary formats ([HRX](../docs/hrx.md)).
- **Loom model programs, behind a gate.** `1bit serve` can now hand a model to `loom-serve`, which
  runs AMD's Loom model programs on HRX. A per-model table, `config/loom-routes.json`, decides which
  route serves each model, and a model gets an entry only after it passes an A/B and accuracy gate
  ([Loom route](../docs/loom-route.md), [engine#3166](https://github.com/1bit-MONSTER/engine/pull/3166)).
  The table ships empty in v2026.47: no model is served by Loom in this release yet.
- **The NPU route: our own NPU engine.** The NPU runtime is compiled into `1bit` and runs on the
  in-tree `amdxdna` driver. The release package serves Qwen3-0.6B and Qwen3-4B on the NPU; Qwen3-1.7B follows in the next release
  ([NPU engine](../docs/npu.md), [Releases](../docs/releases.md)).
- **1bit OS.** A Puppy Linux appliance (`ResolutePup64`, Ubuntu 26.04 base) with Lemonade Server and
  the engine inside and our MOK-signed `7.4.0-rc1-1bit` kernel. It boots headless, with a desktop
  entry in the boot menu; `bash`, `sudo` and `apt` work, and models, Lemonade's config and SSH keys
  live on the persistent `1BIT-DATA` partition ([1bit OS](../docs/os-v3.md)).
- **Install to disk.** `1bit-install <disk> --yes` from the live session puts the same system on an
  internal disk, as a persistent system with its own boot entry ([Install 1bit OS](../docs/install.md)).
- **The package.** Already running Lemonade on Ubuntu? The `lemonade-onebit` package adds the engine
  as a Lemonade backend; nothing else changes ([Lemonade](../docs/lemonade.md)).

The Lemonade release inside v2026.47 is the weekly pin, listed in the release notes.

## Get it in three steps: boot Strix Halo from a USB stick

1. **Download** `1bit-os-v2026.47.img.zst` and `SHA256SUMS` from the
   [v2026.47 release](https://github.com/1bit-MONSTER/engine/releases/tag/v2026.47). The same page carries the release notes and the `lemonade-onebit`
   package.
2. **Write it** to the whole USB disk (16 GB or more; `/dev/sdX` is the stick, not a partition):

   ```sh
   sha256sum -c SHA256SUMS --ignore-missing
   zstd -d 1bit-os-v2026.47.img.zst
   sudo dd if=1bit-os-v2026.47.img of=/dev/sdX bs=4M conv=fsync status=progress
   ```

3. **Boot** the Ryzen AI MAX+ 395 from the stick. Lemonade comes up with its catalog and web UI.
   Secure Boot can stay on where our key is enrolled; on a machine that has never trusted it, enroll
   the key first or turn Secure Boot off ([Install 1bit OS](../docs/install.md)).

The stick image is assembled from the exact files that passed on the hardware: the kernel, the
initrd and the OS filesystems are verified by checksum against the tested candidate, and the image
is boot-checked with Secure Boot on.

To keep it, run `1bit-install <disk> --yes` from the live session. Connecting a client (`curl`, the
web app, the phone app, the OpenAI SDKs) is [Clients](../docs/clients.md); the
[Strix Halo guide](strix-halo.html) sums up what runs where.

## Roadmap: Loom on HRX, the NPU engine, more models

- **Whole-model Loom programs on HRX.** Models move to whole-model Loom programs one by one as they
  pass the speed + accuracy gate, served by `loom-serve` behind `1bit serve`. A model moves only after an
  interleaved A/B on the Strix Halo box (at least four rounds per arm, against the current route)
  and an accuracy check: greedy agreement on fixed prompts, and KL divergence and same-top-token
  rate against the CPU. It moves only when Loom is not worse on accuracy and is faster
  ([Loom route](../docs/loom-route.md), [engine#3158](https://github.com/1bit-MONSTER/engine/issues/3158)).
  The first candidate entry, Qwen3.8-27B UD-Q4_K_XL, is drafted and waits on its accuracy re-run
  ([engine#3261](https://github.com/1bit-MONSTER/engine/pull/3261)).
- **Loom coverage.** Our shipped models are mapped against the published Loom cards; models without
  one get Loom programs written for them with loom-skills and weaver
  ([engine#3156](https://github.com/1bit-MONSTER/engine/issues/3156)). Models with multi-head latent
  attention (GLM-4.7-Flash, the DeepSeek-R1 class) need that path first
  ([engine#3221](https://github.com/1bit-MONSTER/engine/issues/3221)). Until a model moves, the
  llama.cpp route serves it, and it stays as the fallback.
- **The NPU engine.** More models, faster prefill, and several requests sharing one decode pass,
  each answer identical to its own run ([engine#2714](https://github.com/1bit-MONSTER/engine/pull/2714)).
- **Hybrid NPU prefill, GPU decode.** The hybrid route processes the prompt on the NPU and generates
  on the GPU ([Hybrid](../docs/hybrid.md)); handing the NPU's prefill to Loom decode is
  [engine#3157](https://github.com/1bit-MONSTER/engine/issues/3157).
- **Broader model coverage, including small machines.** The LFM3 family, smallest first, for 16 GB
  machines ([engine#2918](https://github.com/1bit-MONSTER/engine/issues/2918)), and every
  architecture the registry maps, checked before it is listed ([Model registry](../docs/registry.md)).

## Known limits

- **No model runs on Loom in this release.** The route is in `1bit serve`, and its table is empty
  until a model passes the gate.
- **The NPU serves Qwen3-0.6B and Qwen3-4B in this release.** Qwen3-1.7B on the NPU follows in the next
  release. Other models run on the GPU.
- **One machine, one OS.** The engine is built and measured on the Ryzen AI MAX+ 395 on Linux.
  There is no Windows package; on Windows, Lemonade serves with its own backends.
- **Bosgame BeyondMax USB.** The ports work with the keep-awake rule that 1bit OS ships; USB4 and
  Thunderbolt devices on those ports are untested ([Known issues](https://github.com/1bit-MONSTER/engine/blob/main/KNOWN-ISSUES.md)).
- **Long-context decode on the HRX route** is slower than short-context decode: 9.70 tok/s at
  18.8k tokens of context in the measurement on
  [engine#679](https://github.com/1bit-MONSTER/engine/issues/679). That work is parked while the GPU
  route moves to Loom.
- **Five release-check rows are open**, the same on the stick and the installed disk, each named for
  the next release: two stale NPU-set checks, a library path cleanup, a USB-capture tool, and a
  queued non-streamed NPU chat case ([Releases](../docs/releases.md)).
- **The NPU route does not take tool calls yet.** A request with `tools` to an NPU model is refused
  with a clear message.
- **Secure Boot** on a machine that has never trusted our key needs the key enrolled, or Secure Boot
  off ([Install 1bit OS](../docs/install.md)).
- The issues still open at the cut are on the
  [tracker](https://github.com/1bit-MONSTER/engine/issues).

## Frequently asked questions

### Does the 1bit engine run LLMs on the AMD Ryzen AI NPU on Linux?

Yes. The NPU engine runs on the XDNA 2 NPU of the Ryzen AI MAX+ 395 on Linux, with the in-tree
`amdxdna` driver, and its runtime is compiled into `1bit`. The release package serves Qwen3-0.6B
and Qwen3-4B on the NPU; Qwen3-1.7B follows in the next release. On the release build, Qwen3-0.6B
decodes at 91.7 tok/s on the NPU in the bench and chats at up to 98.2 tok/s
([v2026.47 on the hardware](../docs/releases.md#v202647-22-nov-2026--the-first-published-release), [NPU engine](../docs/npu.md)).

### Which hardware does it run on?

The AMD Ryzen AI MAX+ 395 (Strix Halo): its Radeon 8060S iGPU (`gfx1151`) and its XDNA 2 NPU, on
Linux. On the release build it boots from a USB stick to Lemonade serving in about 74 s, and
Qwen3-4B-Instruct-2507 runs at 46.5-50.0 tok/s on the GPU. Every number in the docs was measured on
that machine ([v2026.47 on the hardware](../docs/releases.md#v202647-22-nov-2026--the-first-published-release), [Models measured](../docs/models.md)).

### How do I install it?

Write 1bit OS to a USB stick, boot from it, and Lemonade serves; `1bit-install <disk> --yes` puts
the same system on a disk. On an Ubuntu that already runs Lemonade, the `lemonade-onebit` package
adds the engine as a backend ([Install 1bit OS](../docs/install.md), [Lemonade](../docs/lemonade.md)).

### Which models does it run?

On the GPU, any GGUF the HRX llama.cpp build loads, in every ggml weight type; the models checked on
the hardware include Qwen3.8-27B, Qwen3.8-Flash-Next, ZAYA1-8B, Ternary-Bonsai-2-27B, BitNet b1.58,
LFM3-1.7B and gpt-oss-20b. On the NPU, Qwen3-0.6B and Qwen3-4B; Qwen3-1.7B follows in the next release ([Models measured](../docs/models.md)).

### Does it use AMD's Loom on HRX?

The HRX route's kernels are Loom kernels today. Whole-model Loom programs, served by `loom-serve`,
are wired into `1bit serve` and switch on per model once a model passes the A/B and accuracy gate;
no model has passed it in v2026.47 ([Loom route](../docs/loom-route.md)).

### Is it open source?

The source code is Apache-2.0 on [GitHub](https://github.com/1bit-MONSTER/engine). The release
binaries also contain two proprietary components, compiled in: the 1bit NPU runtime and the 1bit
HIP kernels for HRX. They ship under the 1bit Binary License, free to use for any purpose and to
pass on unmodified. A build from the source without them has no NPU engine and runs HRX on the
public kernels only ([Meet the engine](overview.html)).
